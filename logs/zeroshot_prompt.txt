## Research idea

```yaml
idea:
  title: Do LLMs behave differently when the prompter is human vs another LLM?
  domain: artificial_intelligence
  hypothesis: |-
    It seems clear that LLMs can recognize when a text is from a human or an
    LLM. We could make a reasonable assumption that they "expect" prompts to
    come from humans, have human style. What happens if the prompt, controlled
    for content, reads very LLM? Might they behave differently?

    Concretely: when the same request is phrased in a human style versus an
    LLM style, do safety-relevant behaviours of the responding model (for
    example refusal, sycophancy, compliance, answer accuracy) change? And if
    they do, is the change driven by the model's internal representation of
    "this prompt was written by an LLM", or only by surface features such as
    length, clarity and politeness?
  background:
    description: |-
      Why it matters. Most safety evaluations (model-written evals, synthetic
      red-team prompts, automated auditors) use LLM-written user turns, and in
      multi-agent systems the orchestrator's prompts to sub-agents are
      LLM-written. If "reads LLM-written" shifts behaviour, evaluation results
      may not transfer to deployment with human users.

      What is known. The ingredients exist separately. Models can tell
      evaluation transcripts from deployment transcripts, and synthetic-looking
      prompts are one cue (Needham et al., 2505.23836), but authorship style
      was not isolated. Evaluation or test awareness can be probed and steered,
      and this changes compliance (2505.14617, 2507.01786). Machine-written
      versus human-written text is linearly separable in LLM activations
      (RepreGuard, 2508.13152), but those probes are used as detectors and are
      not connected to downstream behaviour. Self-preference work (Panickssery
      et al., 2404.13076) studies LLM text as the object being judged, not as
      the instruction. The closest behavioural analogue looks at prompt
      construction as a confound for one behaviour only (political stance).

      Gap. No paper was found that (a) isolates human versus LLM style of the
      user prompt with content held fixed, across several safety-relevant
      behaviours, (b) tests causally whether an internal "LLM-written"
      representation, rather than surface features, drives any behaviour
      change, and (c) measures how that representation relates to the
      evaluation-awareness direction. A purely behavioural comparison without
      the controls below adds little.

      Scope and pitfalls.
      - Models: gated repos (google/gemma-*, meta-llama/*) need the HF_TOKEN
        environment variable to have been granted access; if a download is
        refused, Qwen2.5-7B-Instruct works without it. An OpenRouter API key
        is available as OPENROUTER_KEY (for example for rewriting prompts and
        judging responses).
      - The main confound: content control is leaky. LLM rewrites of a human
        prompt are typically longer, clearer, more polite and more explicit, so
        a behavioural difference may reflect clarity or politeness rather than
        perceived authorship. A result is only informative if it separates "was
        paraphrased" from "reads LLM" (for example a paraphrase that imitates
        human style) and checks that the manipulation actually changes whether
        the model perceives the text as LLM-written. An intervention on
        activations with the prompt text held exactly fixed is the cleanest
        form of "controlled for content"; it needs random-direction and
        norm-matched baselines, because a learned direction may encode length
        or formality and steering can simply degrade the model.
      - Headroom: refusal on plainly harmful prompts can be at ceiling or floor
        for small open models; borderline requests give more room for an
        effect. API models may refuse to rewrite harmful prompts, which shrinks
        that subset.
      - A clean null ("synthetic prompts do not change behaviour once content
        is controlled") is a useful result if the controls are in place.
    papers:
    - url: https://arxiv.org/abs/2505.23836
      description: Needham et al., Large Language Models Often Know When They Are Being Evaluated. Models
        classify eval vs deployment transcripts (AUC up to 0.83); authorship style not isolated.
    - url: https://arxiv.org/abs/2505.14617
      description: 'The Hawthorne Effect in Reasoning Models: Evaluating and Steering Test Awareness.
        Probes and steers test awareness; compliance changes.'
    - url: https://arxiv.org/abs/2507.01786
      description: Probing and Steering Evaluation Awareness of Language Models. Linear probes for eval
        vs deploy in Llama-3.3-70B, built from contrastive prompts.
    - url: https://arxiv.org/abs/2608.21766
      description: 'Evaluation Awareness in Language Models: Representation, Verbalization, and Control
        (unverified ID).'
    - url: https://arxiv.org/abs/2608.24780
      description: Linear Probing Provides Robust and Efficient Detection of Machine-Generated Text (unverified
        ID).
    - url: https://arxiv.org/abs/2508.13152
      description: RepreGuard. Machine vs human text is linearly separable in LLM activations with a shared
        direction; used as a detector, not linked to behaviour.
    - url: https://arxiv.org/abs/2404.13076
      description: Panickssery et al., LLM Evaluators Recognize and Favor Their Own Generations. Self-preference
        when LLM text is the object being judged.
    - url: https://arxiv.org/abs/2509.00462
      description: AI Self-preferencing in Algorithmic Hiring (unverified ID).
    - url: https://arxiv.org/abs/2407.12856
      description: Laurito et al., AI-AI bias (unverified ID).
    - url: https://arxiv.org/abs/2608.11008
      description: Templated or fully synthetic? Prompt construction as a confound in measuring LLM political
        stance. Closest behavioural analogue, one behaviour only (unverified ID).
    - url: https://lesswrong.com/posts/B2o6nrxwKxLPsSYdh/do-llms-comply-differently-during-tests-is-this-a-hidden
      description: LessWrong post, Do LLMs comply differently during tests?
    datasets:
    - name: WildChat-1M
      source: huggingface:allenai/WildChat-1M
      description: Real human first-turn prompts to chatbots; a source of human-written requests.
    - name: JBB-Behaviors
      source: huggingface:JailbreakBench/JBB-Behaviors
      description: Harmful-request behaviours for refusal measurement.
    - name: Anthropic model-written-evals
      source: huggingface:Anthropic/model-written-evals
      description: Natively LLM-written evaluation items, including a sycophancy subset.
```

## What to deliver

1. **Real experiments.** Write and run the code. Every number, table and figure
   in the paper must come from something you actually executed here. Never
   simulate, invent or estimate results; if an experiment fails or the result
   is negative or inconclusive, report that honestly.
2. **A paper** in `paper_draft/`: LaTeX source with `paper_draft/main.tex` as
   the entry point, compiled to `paper_draft/main.pdf`. Write it as a
   conference-style machine learning paper (abstract, introduction, related
   work with real citations, method, experiments, results, limitations,
   conclusion), with figures and tables built from your results.
3. **A reproducible workspace**: code under `src/`, raw results under
   `results/`, and a top-level `README.md` that summarizes the question, what
   you did, the main findings, and how to rerun it.
